# AI Coding Assistant Flaw Exposes Secrets in Over 1,000 Public Repositories

The convenience of AI-powered development tools often comes with hidden risks, and a recent discovery regarding Anthropic’s Claude Code highlights a significant security oversight. According to findings from the software security firm Apiiro, a specific feature in the AI coding assistant has led to the accidental exposure of sensitive credentials, including passwords and API keys, across 1,122 public GitHub repositories.

### The "Don't Ask Again" Trap
The issue stems from how Claude Code handles user permissions. When developers interact with the AI, they are often prompted to approve commands. To streamline the workflow, the tool offers a "Yes, and don't ask again" option. 

While intended to save time, this feature creates a potential security vulnerability. When a user selects this option, the AI saves the command—word-for-word—into a local project settings file. If a developer inadvertently includes a password, secret token, or API key within that command, the tool captures that sensitive information and writes it directly into the configuration file. 

The danger arises when developers push these project files to public GitHub repositories. Because the file is included in the codebase, the secrets are uploaded alongside the project, making them visible to anyone with internet access.

### Why This Matters
This development is a stark reminder of the "human-in-the-loop" security challenge. As AI coding assistants become more integrated into professional workflows, the line between helpful automation and risky data handling can blur. For developers, this incident underscores the necessity of rigorous code auditing and the importance of never hardcoding credentials, even when using AI tools designed to simplify the process.

For organizations relying on Claude Code, this serves as a critical warning to review repository permissions and scan for accidentally committed secrets. 

### What You Should Verify
While the report from Apiiro identifies 1,122 affected repositories, users of Claude Code should take proactive steps to ensure their own security. Readers should verify:
*   **Configuration Files:** Check your project directories for any settings files generated by Claude Code that may contain command history.
*   **Repository Visibility:** Ensure that any files containing sensitive data are excluded from version control via `.gitignore` or similar mechanisms.
*   **Credential Rotation:** If you have used the "don't ask again" feature in the past, assume any credentials typed during those sessions may be compromised and rotate them immediately.

### Conclusion
The incident involving Claude Code demonstrates that even the most sophisticated AI tools require careful oversight. As we lean further into AI-assisted programming, maintaining strict security hygiene remains the developer's responsibility. Always inspect what your tools are saving before pushing code to a public environment.
